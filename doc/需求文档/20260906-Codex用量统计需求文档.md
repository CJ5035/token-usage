# Codex 用量统计集成需求方案

> 创建日期：2026-09-06
> 状态：待实施

## 一、需求概述

本需求中的“获取 token 秒速”统一解释为 token 生成速度（tok/s），不解释为首 token 延迟（TTFT）。参考 Codex session 日志只在存在明确单次请求耗时字段时才能计算真实 tok/s；当前参考格式通常没有该字段，因此当前版本必须正确显示 `—`，不得使用相邻请求间隔冒充生成耗时。

参考 `F:\GitHubs\zai-floating-monitor` 的 Codex 会话日志解析方式，在 GoGauge 中增加 Codex CLI 本地用量统计。程序读取本机 `~/.codex/sessions` 下的 JSONL 会话记录，解析 token 用量并纳入现有首页报表、统计页和记录页。

功能必须提供 Codex 用量总量、今日用量、按模型统计、按渠道统计，以及 token 获取速度（tok/s）指标。数据应支持增量读取、重复导入幂等、无 Codex 数据时的空状态展示，并与现有时间范围和渠道筛选保持一致。

## 二、参考实现与口径结论

参考项目的主要实现方式如下：

- 数据源为 `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`，支持通过环境变量覆盖 Codex 根目录。
- `event_msg` 且 payload 类型为 `token_count` 的事件是用量来源。
- 每条用量取 `info.last_token_usage`，字段包括 `input_tokens`、`cached_input_tokens`、`output_tokens`、`reasoning_output_tokens` 和 `total_tokens`。
- `token_count` 事件本身通常不带模型名，模型由同一会话中最近的 `turn_context.model` 归属。
- 以 `(session_id, event_seq)` 作为导入库唯一键，并保存文件读取偏移，重复扫描或文件重写时保持幂等。
- `provider_id` 在 Codex 数据中通常默认为 `codex`，日志不一定包含真实的中转渠道字段。

因此，渠道统计以日志中的 `provider_id` 为唯一来源。参考实现默认值为 `codex`，当前日志没有明确 provider/channel 时全部归入 `codex`；不根据模型名称推导渠道。只有日志提供明确的请求耗时字段时才计算真实 tok/s；否则不把相邻请求的时间间隔当作生成耗时，Codex 的速度值返回 NULL，界面显示 `—`。如果未来发现可可靠关联的流式事件，再以独立字段增加“事件间隔估算”，不与真实速度混用。

## 三、功能边界

### 包含范围

- 扫描 Codex 会话目录并增量解析 JSONL。
- 解析 token_count 事件中的输入、输出、缓存、reasoning 和总 token。
- 归属会话、模型、provider/channel、事件时间。
- 通过本地 SQLite 镜像表保存 Codex 记录和文件进度。
- 将 Codex 纳入现有自动同步流程和统计刷新流程。
- 统计总量、今日、当前时间范围、按模型、按渠道和每日趋势。
- 提供 token 生成速度字段，单位为 `tok/s`；只有日志包含明确单次请求耗时且样本有效时才显示数值，否则显示 `—` 并说明原因。
- 在首页统一渠道 Tab、渠道明细、趋势图、渠道占比和渠道概览中显示 Codex。
- 首页顶部总量、今日、输入、输出、请求和费用等公共 KPI 必须与首页渠道明细使用同一合并口径，包含 Codex。
- 在统计页增加 Codex 专属统计区块。
- 在记录页增加确定的数据源筛选和 Codex 明细展示，保证采集到的数据可追溯。
- 更新关于页、欢迎页和页脚的数据来源与功能文案，反映 Codex 已接入。
- 支持 Codex 会话目录不存在、文件损坏、半行 JSON、字段缺失等降级场景。

### 不包含范围

- 不修改 Codex 原始 JSONL 文件。
- 不向 Codex 服务端发起额度查询或登录请求；本需求只统计本地会话日志。
- 不把 Codex 本地数据伪装成 OpenCode 账号，也不新增 Codex 登录凭证配置。
- 不承诺从现有日志推导真实 TTFT、真实网络耗时或单次响应生成时长；无明确耗时字段时不计算 tok/s。
- 不改造账户总览页的 OpenCode/BAI/CommandCode 账号模型；Codex 作为本地数据源接入公共渠道报表。
- 不在本阶段实现 Codex 远程同步、跨设备合并或云端备份。

## 四、核心实体定义

### `codex_usage`（本地镜像记录）

- **用途**：保存一条从 Codex session JSONL 解析出的 token_count 用量事件。
- **关键属性**：
  - `id: String` — 稳定的导入唯一键，建议由 `session_id + event_seq` 组成。
  - `session_id: String` — rollout 文件对应的会话标识。
  - `event_seq: Integer` — 会话内事件序号。
  - `started_at: String` — 事件时间，统一存 UTC ISO 8601。
  - `model: String` — 最近一次 `turn_context.model` 归属的模型；无法识别时使用空值或 `unknown`。
  - `provider_id: String` — provider/channel 标识，参考实现默认值为 `codex`；无法识别时也为 `codex`。
  - `input_tokens: Integer` — 输入 token。
  - `output_tokens: Integer` — 输出 token。
  - `cache_read_tokens: Integer` — 缓存输入 token。
  - `reasoning_tokens: Integer` — reasoning 输出 token。
  - `total_tokens: Integer` — 日志提供的总 token；缺失时按已解析字段求和。
  - `speed_tps: Real` — 仅在日志提供明确耗时字段时计算的 token 秒速；无明确耗时字段时为 NULL。
  - `speed_source: String|null` — `duration` 或 NULL，用于说明速度来源。
  - `model_revision_at: Integer` — 模型上下文修订序号，用于后续补齐先入库的空模型记录。
  - `source_file: String` — 原始 JSONL 文件路径，用于诊断和追溯。
  - `synced_at: String` — 写入 GoGauge 数据库的时间。
- **关联关系**：多条记录属于一个 `session_id`，按 `model` 和 `provider` 聚合。

### `codex_file_progress`（文件进度）

- **用途**：记录每个 rollout 文件的增量读取位置。
- **关键属性**：
  - `path: String` — 文件绝对路径，主键。
  - `offset: Integer` — 最后一条完整 JSONL 行的字节结束位置。
  - `size: Integer` — 上次扫描时文件大小。
  - `updated_at: String` — 进度更新时间。
- **关联关系**：一个文件进度对应一个 JSONL 文件；文件变短时从头扫描，依靠记录唯一键去重。

### CodexSummary（统计响应）

- **用途**：向前端提供 Codex 统计页和公共报表所需的聚合数据。
- **关键属性**：
  - `range: String` — `today`、`yesterday`、`7d`、`30d` 或 `all`。
  - `totals: Object` — 当前范围总请求数、输入、输出、缓存、reasoning、总 token、平均/最快 tok/s；无速度字段时为 NULL。
  - `today: Object` — 今日同口径统计，且与首页今日 KPI 使用同一数据口径。
  - `channels: Array` — 按 provider/channel 聚合。
  - `models: Array` — 按模型聚合，至少携带 channel/provider。
  - `daily: Array` — 每日 token 和请求趋势。
  - `db_found: Boolean` — 是否检测到 Codex 会话目录或已有镜像数据。
  - `last_import_at: String|null` — 最近一次导入时间。
  - `import_error: String|null` — 最近一次导入错误，供诊断展示。

## 五、页面与接口影响范围

### 1. 首页：公共渠道报表

首页已有通用渠道组件，因此不新增独立 Codex 首页卡片，但必须修改数据链路和渲染逻辑：

- 渠道 Tab 中增加 `codex`。
- 渠道明细表增加 Codex 的 token、输入、输出、缓存、请求数和费用/估算标识。
- 分渠道趋势图增加 Codex series。
- 渠道占比图增加 Codex 数据。
- 单渠道概览、单渠道趋势和小时趋势支持 `channel=codex`。
- `全部渠道`统计必须包含 Codex，且与各渠道行合计一致。

涉及页面文件：

- `app/web/index.html`：仅在公共组件无法承载标识时补充 Codex 文案或空态节点。
- `app/web/app.js`：渠道列表、首页报表、渠道切换、趋势和占比的 Codex 兼容。

### 2. 统计页：Codex 专属区块

新增与 ZCode/Claude Code 结构一致的 Codex 区块：

- 总量 KPI：请求数、总 token、输入 token、输出 token、估算平均 tok/s。
- 今日 KPI：今日请求数、今日总 token、今日输出 token、今日估算平均 tok/s。
- 渠道明细表：渠道、请求数、总 token、输入、输出、tok/s；当前无明确耗时字段时显示 `—`。
- 模型明细表：模型、渠道、请求数、总 token、输入、输出、tok/s；当前无明确耗时字段时显示 `—`。
- 近期趋势图：按日展示总 token 和请求数。
- 无数据状态：显示未发现 `~/.codex/sessions` 或环境变量指定目录。
- 速度提示：明确“Codex 日志未提供明确耗时时显示 `—`”；未来出现明确耗时字段后显示真实 tok/s 来源。

涉及页面文件：

- `app/web/index.html`：新增 `codex-stats` 区块、KPI、渠道表、模型表和趋势图容器。
- `app/web/app.js`：新增 `loadCodexSummary`、Codex 数据渲染、时间范围切换和语言切换刷新。
- `app/web/style.css`：仅在现有 `zcode-stats` 样式不足以承载 Codex 区块时补充样式。

### 3. 记录页：Codex 可追溯明细

由于 Codex 数据保存在独立镜像表，现有 `usage_records` 查询不会自然显示 Codex。记录页统一扩展现有查询接口，增加 `source=all|opencode|codex` 筛选；后端将两个来源归一为同一响应结构，前端沿用现有表格和分页，不新增第二套记录表。

- 增加数据源筛选：全部、OpenCode、BAI、CommandCode、ZCode、Claude Code、Codex；默认保持当前 OpenCode 行为或按用户最近选择恢复。DSH 没有持久化明细表，不纳入记录页明细筛选。
- Codex 行显示时间、模型、渠道、输入、输出、缓存、reasoning、总 token、tok/s；无明确耗时字段时显示 `—`。
- 会话聚合支持 Codex session_id；现有“会话用量”区域也必须支持 `source=all|opencode|codex`，不能只改明细记录表。
- 空数据和导入失败显示与其他本地数据源一致的状态。

涉及页面文件：

- `app/web/index.html`：记录页筛选控件和必要列。
- `app/web/app.js`：记录查询、来源筛选、Codex 字段渲染和分页。

### 4. 关于页、欢迎页、设置页、账户总览页

- 关于页、欢迎页和页脚必须更新产品简介、功能列表和数据来源文案，明确包含 Codex CLI 本地日志统计。
- `app/web/app.js` 中的中英文国际化字典必须同步增加 Codex 名称、无数据、导入失败、速度口径和数据目录文案。

- 账户总览页不纳入 Codex，因为它展示的是账号实体；Codex 在首页公共渠道报表和统计页展示。

### 后端接口

#### `GET /api/codex/summary?range=<range>`

返回当前时间范围的 Codex 专属聚合。接口触发后台增量导入后立即返回缓存/已有数据，避免页面等待文件全量扫描。

#### `GET /api/codex/records?page=<n>&page_size=<n>&model=<model>`

返回 Codex 明细分页，字段包含模型、渠道、时间、token 明细、总 token 和 tok/s；当前日志没有明确耗时时 tok/s 为 NULL，前端显示 `—`。

#### 现有 `/api/usage/records` 与 `/api/usage/sessions`

两个现有接口新增 `source=all|opencode|bai|commandcode|zcode|claudecode|codex` 参数。`records` 返回统一明细字段，`sessions` 返回统一会话聚合字段；当 `source=codex` 时查询 `codex_usage`，当 `source=all` 时合并已有持久化来源并按时间倒序/会话维度返回。Codex 不依赖 OpenCode 登录状态即可查询。

#### 现有 `/api/report/*`

扩展现有公共报表的 Codex 数据源：

- `/api/report/windows`
- `/api/report/daily`
- `/api/report/hourly`
- `/api/report/channels`
- `/api/report/channel-overview`
- `/api/report/channel-trend`

所有接口的 `channel=codex` 和不传 channel 的全部渠道模式都必须支持 Codex，且范围、时区和合计口径一致。接口读取统计前触发 Codex 增量导入；导入在后台执行时先返回已有镜像数据，下一次刷新显示新数据。

各接口必须按以下规则实现：

- `/api/report/windows`：Codex 纳入 today、yesterday、7d、30d 及同时段比较。
- `/api/report/daily`：Codex 作为独立 `codex` series，支持 tokens、cost、requests 三种 metric。
- `/api/report/hourly`：Codex 按本地时区小时聚合，支持 today 和 yesterday。
- `/api/report/channels`：返回 Codex 渠道行，字段与其他渠道一致；本地估算费用使用 `estimated=true`。
- `/api/report/channel-overview`：`channel=codex` 返回 Codex totals；默认首页总览 KPI 与渠道行使用相同合并口径。
- `/api/report/channel-trend`：`channel=codex` 返回 Codex 24 小时趋势。

首页 `/api/dashboard` 返回的顶部总量、今日、输入、输出、请求和费用也必须合并 `codex_usage`；不能只在前端渠道表中追加 Codex，否则首页 KPI、渠道明细和图表会互相不一致。

## 七、数据口径与异常处理

### Token 口径

- `input_tokens`：日志中的输入 token。
- `cache_read_tokens`：`cached_input_tokens`，单独展示并纳入总 token。
- `output_tokens`：日志中的输出 token。
- `reasoning_tokens`：`reasoning_output_tokens`。
- `total_tokens`：优先使用日志 `total_tokens`；只有字段缺失时才回退计算。当前参考项目的映射为输入 + 缓存读 + 输出 + reasoning，正式实现前必须用真实样本确认四项是否存在包含关系；如果日志总量已包含某项，不能再次累加该项。
- 统计按记录求和，不重复把累计总量和单次增量同时计入。

### 渠道口径

- 优先使用记录中明确的 provider/channel 字段。
- 没有明确 provider/channel 时使用 `codex`。
- 不使用模型名推导渠道，避免把 `gpt-5.3-codex` 等模型错误当成供应渠道。
- 前端渠道展示名称使用统一渠道映射，未知值 HTML 转义后原样显示。

### token 秒速口径

- 持久化字段为 `speed_tps`，聚合字段为 `avg_tps` 和 `max_tps`，并返回 `speed_source`。
- 只有日志提供明确的单次请求耗时字段（例如 `duration_ms`）时才计算 tok/s，公式为 `output_tokens * 1000 / duration_ms`。
- 当前参考格式没有明确单次请求耗时字段时，Codex 的 `speed_tps`、`avg_tps` 和 `max_tps` 返回 NULL，前端显示 `—`。
- 不使用相邻 token_count 事件之间的时间差作为默认生成耗时；未来如确认存在可靠的流式事件，再单独定义“事件间隔估算”字段和展示文案。
- 不新增 `avg_ttft_ms`，因为 Codex 日志无法可靠提供首 token 延迟。

### 异常处理

- Codex 目录不存在：接口返回 `db_found=false`，统计页显示空态，公共报表不增加空渠道。
- 单行 JSON 非法：跳过该行并继续推进到下一条完整行。
- 文件末尾为半行：不消费半行，保留 offset 等待下次补全。
- 文件变短或重写：从头扫描，依靠唯一键幂等。
- 模型上下文暂缺：记录可落库但模型显示 `unknown`；后续重新扫描允许补齐模型归属。
- 单文件读取失败：跳过该文件并记录最近一次导入错误，不阻塞其他来源同步。
- 导入失败：统计接口继续返回上一份可用数据或空结果，前端显示非阻塞错误状态。

## 八、测试与验收标准

### 单元测试

- 解析合法 `token_count` 事件并正确映射五类 token 字段。
- 使用最近的 `turn_context.model` 归属模型。
- 缺少 provider/channel 时归入 `codex`。
- session_id 和 event_seq 生成稳定，重复解析不产生重复记录。
- 增量 offset 只推进到完整行末尾，半行下次可继续读取。
- 文件截断后可从头重扫且不重复计数。
- 非法 JSON、缺失 payload、空 token usage、缺时间戳的行不会中断批次。
- 估算 tok/s 的可信样本、异常样本和无样本结果符合口径。

### 数据库与 API 测试

- Codex 导入支持新增、更新和幂等去重。
- 总量与今日统计边界按本地自然日正确计算。
- 分模型和分渠道合计等于 Codex 总量。
- `report_channels`、`report_windows`、`report_daily`、`report_hourly`、`channel_totals`、`channel_trend` 在 `codex` 和全部渠道模式下均包含正确数据。
- Codex 不存在或无记录时不污染其他渠道统计。
- `/api/codex/summary` 和 `/api/codex/records` 返回稳定字段、空态和错误降级结果。

### 前端验收

- 统计页能显示 Codex 总量、今日、分模型、分渠道和 tok/s 字段状态；当前日志无明确耗时时正确显示 `—` 并显示无速度数据原因。
- 首页渠道 Tab 能选择 Codex；首页全部渠道合计包含 Codex。
- 首页渠道明细、趋势、占比、单渠道概览和小时趋势均能显示 Codex。
- 记录页能在全部已有来源与 Codex 之间筛选，并查看 Codex 记录及 tok/s 字段状态。
- 切换时间范围、语言、主题和页面时，Codex 区块不会丢失或显示旧数据。
- Codex 目录不存在、无速度样本、导入失败时页面不崩溃、不出现 `undefined` 或未转义 HTML。
