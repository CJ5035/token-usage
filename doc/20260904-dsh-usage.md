# DSH 本地耗用量接入实施文档

> 状态：**已实施完成**（2026-09-04，SDD 双任务 + 全分支评审通过；改动待人工确认签入）
> 日期：2026-09-04
> 参照：F:\GitHubs\zcode-desktop（`src/data/dsh.js` 与 `src-tauri/src/data/dsh.rs`）

## 1. 背景与目标

GoGauge 目前支持 opencode / BAI / commandcode（账户体系）与 ZCode（本地 sqlite，独立数据域，
见 `doc/20260903-zcode-integration.md`）的用量展示。用户希望以 zcode-desktop 的方式获取
**DSH**（本机编码 CLI，deepseek harness）的 token 耗用量。

已确认的需求边界：

1. **展示形态**：独立本地用量区块（同 ZCode 模式），**不进 accounts 体系**（dsh 无账号/token 概念）。
2. **展示粒度**：总量 + 今日 + 分渠道（provider）+ 分模型（model）+ **token 秒速（tok/s）**。

## 2. 调研结果（均已在本机数据上核实）

### 2.1 zcode-desktop 的获取方式

dsh **没有任何 HTTP 额度接口**，耗用量完全来自本地解析 dsh CLI 的会话日志：

- 数据源：`~/.dsh/sessions/<workspace 目录>/<会话目录>/session.jsonl.zstd`
  （本机实测 413 个文件，单文件最大 6 MB；会话目录名有 `<uuid>` 与 `session-<uuid>` 两种形态，
  通配 `*/*/session.jsonl.zstd` 均可覆盖）。
- 格式：zstd **多帧**压缩的 JSONL 事件流（帧 magic `28 B5 2F FD`，帧头不带内容大小，
  Python 需用 `ZstdDecompressor().decompressobj()` 流式解压，`decompress()` 会报
  "could not determine content size in frame header"，已实测踩坑）。
- 尾帧解压失败 = 正在写入，丢弃该帧即可。

### 2.2 解析与去重口径（dsh.js/dsh.rs 一致，直接沿用）

| 事件 | 作用 |
|---|---|
| `request/context` | 声明当前 `provider/model`，其后的 usage 归该渠道×模型 |
| `assistant/chunk`（`chunk.type=="usage"`） | usage 样本（实测与最终值相同） |
| `assistant/message`（`data.usage`） | 最终 usage，**覆盖**同 `turn:step` 的 chunk 样本（不累加） |
| `step/start`（`data.turn/step` + 顶层 `time` 毫秒） | 秒速窗口起点 |
| `session` / `session/title` / `user/message` 等 | 元信息（本次不需要） |

- token 口径：`input = inputTokens + cacheReadTokens + cacheWriteTokens`（billed 口径），
  cache 单独拆出；`outputTokens`、`reasoningTokens` 独立。
- 实测 40 个近期日志的 usage 字段全集：**只有 `inputTokens / outputTokens / cacheReadTokens`**
  （cacheWrite/reasoning 代码上仍按可选取 0 兼容）。
- **无费用字段、无时长字段** → 秒速需自行用时间戳计算（见 4.1）。
- 实测渠道（provider）取值：`commandcode-go2`、`vision-toolkit-opencode-go2`、
  `vision-toolkit-wechat-codingplan`；模型：`Deepseek-v4-flash`、`muse-spark-1.x-contributor` 等。
- zcode-desktop 每次全量扫描 + 15s TTL 内存缓存。其 Electron 版曾因 V8 GC 特有坑 OOM，
  Python/Rust 无此问题，逐帧流式处理即可。

## 3. 方案选择

**独立数据域**（同 ZCode，`doc/20260903-zcode-integration.md` 第 3 节）：只读
`~/.dsh/sessions`，不写库、不进 accounts、不参与同步。数据缺失时返回 `{found:false}`，
前端显示"未检测到 DSH 本地数据"，不影响其他功能。

## 4. 实施方案

### 4.1 新增 `app/dsh_api.py`（唯一新模块）

```
sessions_root() -> Path                      # ~/.dsh/sessions
decompress_frames(buf: bytes) -> str         # 逐帧找 magic → decompressobj() 流式解压拼接，坏帧丢弃
_tokens_from_usage(u: dict) -> dict | None   # input=billed口径, cache, output, reasoning
stat_log(log_path, sid) -> dict | None       # 单会话: 解析事件流, turn:step 去重,
                                             #   归属 provider/model, 记录每步窗口毫秒
scan() -> dict                               # 聚合总量/今日/分渠道/分模型/秒速
get_dsh_usage() -> dict                      # scan + 模块级 15s TTL 缓存
```

秒速（tok/s）口径（zcode-desktop 无此功能，为本项目新增）：

- 每步生成窗口 = `assistant/message.time − 同 turn:step 的 step/start.time`（毫秒→秒）；
  实测 step/start→step/end 窗口 ≈ 模型生成时段，步间间隔才是工具执行时段，故用 message 时刻收口。
- 步级速率 = `outputTokens ÷ 窗口秒`；聚合速率 = `Σoutput ÷ Σ窗口秒`（加权平均，非简单平均）。
- 噪声剔除（对齐 ZCode 统计页口径）：`outputTokens < 10`、窗口 ≤ 0 或速率 > 500 tok/s 的步
  不参与秒速统计（token 总量仍计入）；`assistant/message` 找不到同 `turn:step` 的
  `step/start` 时视为窗口缺失，同样只计 token、不参与秒速。
- 今日窗口：本地自然日 0 点（与现有统计一致）。

返回结构：

```json
{
  "found": true, "updated_at": "ISO8601", "sessions_count": 413,
  "total": {"input": 0, "cache": 0, "output": 0, "reasoning": 0, "seconds": 0.0, "tps": 0.0},
  "today": {"input": 0, "cache": 0, "output": 0, "reasoning": 0, "seconds": 0.0, "tps": 0.0},
  "providers": [{"provider": "...", "steps": 0, "input": 0, "cache": 0, "output": 0, "seconds": 0.0, "tps": 0.0}],
  "models":    [{"provider": "...", "model": "...", "steps": 0, "input": 0, "cache": 0, "output": 0, "seconds": 0.0, "tps": 0.0}]
}
```

`providers` 按 output 降序，`models` 按 provider+output 降序。目录不存在 → `{found:false, ...}`，
任何单文件损坏跳过不抛异常。

性能：**已实测**（2026-09-04，413 文件全量）：扫描 2.9~3.2s（贴线但 ≤3s 门槛可接受，
zstandard 逐帧解压 + type 子串预过滤；每文件独立构造解压器保证并发安全），
按约定不做 mtime 增量优化；15s TTL 缓存兜底重复请求。

### 4.2 `app/server.py`：一个只读端点

| 端点 | 行为 |
|---|---|
| `GET /api/dsh/usage` | `get_dsh_usage()` 结果直接返回（模块内已带 15s TTL 缓存）；永远 200，数据缺失用 `found:false` 表达 |

不进 `/api/sync`、不进 dashboard payload（避免未装 dsh 的用户首页变慢，前端并发拉取）。

### 4.3 `requirements.txt`

追加 `zstandard>=0.22`（本机已装 0.25.0，当前是间接依赖，需显式声明；PyInstaller 打包无特殊处理）。

### 4.4 前端 `app/web/*`（index.html / app.js / style.css）

**统计页**（`index.html` `#page-stats`）新增「DSH 本地用量」卡片，追加在现有
`#zcode-stats`（ZCode 本地用量卡）之后；**复用统计页现有已实现样式**（`.card` / `.card-h` /
`.kpi-row` / `.tbl`，与 ZCode 区块同款，视觉一致但代码互不依赖、数据各自独立拉取）：

- KPI 两行（各 3 列，复用 `kpi-row` 默认 3 列网格，不改 `style.css` 网格定义）：
  第一行总量：会话数 / 总输入(含缓存) / 总输出；
  第二行今日：今日输入(含缓存) / 今日输出 / 今日秒速 tok/s；
  **总秒速**放卡片头部 `.card-h` 右侧 hint 位（如"平均 12.3 tok/s"）；
- **渠道汇总表**：每渠道一行——渠道名 / 步数 / 输入(含缓存) / 输出 / 平均 tok/s；
- **渠道×模型明细表**：渠道 × 模型 / 步数 / Token 构成 / 平均 tok/s；
- 渠道表与模型表的数字**恒为总量口径**（§4.1 契约仅聚合 today，无 per-provider 今日桶；
  实施时确认的口径）：`.card-h` 内 `.seg`（同模型用量卡 `#mr-dim` 交互）的「总量 | 今日」
  切换只作用于 KPI 两行显隐与 `#dsh-today-note` 口径说明，不跟随统计页 range 药丸；
  若未来需要表格今日档，需在 §4.1 契约追加 per-provider 今日桶；
- `found:false` 时整块显示"未检测到 DSH 本地数据"；
- i18n：zh/en 双语补全（新键约 10 个）。

### 4.6 Dedupe Ticket

- **Intent signature**：新增 `app/dsh_api.py`——解析 `~/.dsh/sessions` 的 zstd 多帧 JSONL，
  聚合 dsh token 用量（总量/今日/分渠道/分模型/tok·s 秒速）。
- **Queries**：codegraph explore "dsh usage 耗用量"；`grep -ri dsh app/`；
  `grep -rn "zstd" app/ tests/`；codegraph explore "zcode_api 本地读取 sqlite"。
- **Top matches**：`app/zcode_api.py`（本地读取模式同类，数据源不同）；
  `app/server.py`（端点挂载层）；`doc/20260903-zcode-integration.md`（模式参照）；
  `tests/test_zcode_api.py`。
- **Decision**：`new`
- **Rationale**：项目内无任何 dsh 相关代码；数据源（zstd 多帧 JSONL）与现有
  sqlite（zcode）/HTTP API（opencode/bai/commandcode）均不同，无法复用，只能新建模块；
  `zstandard` 为必要的显式新依赖。

## 5. 验证方式

1. `python -m py_compile app/dsh_api.py app/server.py`（编译通过）；
2. `python -m pytest tests/ -x -q`（新测试全过、既有测试不回归）；
3. 手动：`python -c "from app import dsh_api; ..."` 打印本机真实数据聚合结果，
   与 zcode-desktop 的 DSH 视图数值抽查对比（同一 billed 口径，应一致或可解释）；
4. 浏览器打开统计页目验新区块渲染与 found=false 分支。

## 6. 边界与风险

- dsh 未安装/无日志 → `found:false`，区块显示空态，其余功能不受影响；
- 日志格式随 dsh 版本演进（本样本已比 dsh.js 编写时新增多种 chunk 事件，但 usage 相关
  结构未变）；解析按"认得的事件取值、不认得的事件跳过"处理，向前兼容；
- 秒速为估算口径（窗口含少量框架开销），文档与前端均标注"平均输出速度（估算）"；
- 全量扫描耗时待实测，二阶段优化（mtime 增量）预留但本次不实现。
