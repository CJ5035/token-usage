# DSH 每日用量与秒速对齐实施计划

> 日期：2026-09-10
> 状态：计划评审通过，可进入实施；共 Review 5 轮，第 4、5 轮连续通过后停止；未修改产品代码

## 一、需求概述

让 DSH 在首页支持今日、昨日、近 7 天、近 30 天、全部范围；用量统计页跟随现有今日、近 7 天、近 30 天、全部四个按钮，展示逐日用量和平均输出 tok/s。昨日汇总从首页“昨天”进入，逐日明细也能在统计页日趋势 tooltip 查看。后端支持全部五种范围，保留现有页面入口数量。现存本地日志提供时间戳与 usage，可直接回算历史，无需等待从今天开始积累。

## 二、方案与功能边界

推荐扩展现有只读扫描和后台缓存：保留去重步骤的紧凑时间/token/计时元数据，按查询范围聚合，再由 server 适配现有报表。避免复制多套独立的今日/历史计算逻辑。

可选方案比较：

| 方案 | 收益 | 代价 |
|---|---|---|
| 扩展现有扫描缓存（推荐） | 改动集中、立即回算历史、沿用本地只读模式 | 冷启动仍需扫描，历史依赖源日志 |
| 新增 DSH 数据库导入子系统 | 重启查询快，可支持日志删除后的历史留存 | 需要迁移、幂等导入、修订与删除策略，超出当前必要范围 |
| 只补统计页日期控件 | 界面改动少 | 首页趋势和多日汇总仍缺 DSH，不能满足渠道对齐 |

包含：每日趋势；首页各窗口、渠道明细、渠道概览与小时趋势接入 DSH；统计页范围统一，渠道/模型明细跟随范围；平均输出速率口径修正及明确的无样本显示；扫描状态和范围切换的必要刷新。

不包含：云端接口、账号登录、费用估算、恢复已删除日志、实时逐 token 流式监控、独立持久化导入子系统。平均输出 tok/s 的分子只用 output，input/cache/reasoning 分列显示，不把所有 token 计为生成速度。

## 三、核心数据与契约

- 去重步骤元数据（内部）：`session_id: str`、`step_key: str`、`completed_ms: int | None`、`provider/model: str`、`input/cache_read/cache_write/output/reasoning: int`、`valid_output: int`、`valid_seconds: float`、`final/unkeyed: bool`。无效日期用 None，不用 0 冒充真实 epoch。不缓存提示词、正文或工具输出。
- 聚合桶：现有字段保留；内部补 `tps_output: int` 与缓存读写分项。`tps = sum(valid_output) / sum(valid_seconds)`，无有效秒数时对外返回 `null`，前端显示 `—`。无效步骤仍参与 token/步数统计。
- 查询摘要（计划新增 `get_dsh_summary(range_: str)`）：从同一后台快照生成所选范围的摘要，精确返回结构见下文。保留 `/api/dsh/usage` 无 range 调用的现有 total/today/providers/models 字段；新前端始终携带 range。旧 tps=0 的无样本语义有意改为 null，所有调用方及相关断言同步迁移。
- 计划新增 `query_dsh_usage(snapshot, range_, now)`：纯查询，按完成时间筛选；结果不与缓存共享可变桶。自然日范围采用本地时区的半开区间，7d/30d 含今日，与 db 现有范围一致。
- 趋势输出经 server 转为 `db.report_daily/report_hourly/channel_trend` 契约；小时固定 24 桶。公共 daily 先合并原始日行，再统一决定日/周/月粒度，不能在已经按周/月输出的报表上直接拼 DSH 日期。各系列在统一 labels 上补零；公共 daily 保持原有“有记录日期的并集”语义，DSH 专用每日趋势单独补齐选定日历区间。
- 费用未知保持 `cost_available=false`，显示 `—`；步数不能直接冒充精确 HTTP 请求数。cache 属于 billed input 的子集，总 token 不再额外加 cache。缓存读写在报表列分开，避免把写入量归为读取。

### 3.1 去重、日期与指标规则（唯一计算源）

1. 先按文件内 turn:step 去重，message 最终 usage 优先于 chunk；同一步多个 message 最后一个有效 usage 胜出，不能让后到 chunk 覆盖已有 message。仅有 chunk 的未完成步骤按已有 usage 计 token，使用该 usage 事件时间；该时刻之后的替换可修订日期归属。缺失/非数值/非有限/负数 turn 或 step 的事件使用带 `unkeyed:` 前缀的文件内行号作独立后备键，不推测多条事件之间的关系，并标 `unkeyed_steps`，说明可能无法去重；合法 key 的 0 值仍有效。每个合法步骤首次有效 usage 保存当时 provider/model，后续覆盖 usage 保留这一归属，避免别的步骤切换全局 context 后把旧步骤错归新渠道。未知 provider 用 unknown，模型缺失保留空串。
2. `session_id` 用相对 sessions_root 的完整会话目录路径作身份，避免不同 workspace 同名目录相撞；查询的 `sessions_count` 为有入选步骤的会话去重数。旧无 range 结果保留文件计数兼容，但新 UI 不用文件数作为范围会话数。
3. 日期使用有效 usage 事件 time（epoch 毫秒）转换的本地完成日；跨日步骤整步归完成日。NaN/Inf/非正数/bool/无法转换的时间归 `undated`；晚于查询 now 的时间归 `future`。二者不进入有日期 totals/providers/models/trend，不丢 token：单独返回诊断桶并显示数量/用量提示。`all` 也只含有效且不晚于 now 的日期记录，因此每日和式恒等于 totals；兼容旧 total 可含 undated/future，但不得作为新范围 KPI。`now` 参数为捕获一次的带时区 datetime；比较用 epoch，自然日零点每一天分别经系统本地时区转换，不能拿 now 的固定 UTC offset 代替历史日 DST offset。
4. 正常范围边界为 today 当地零点、yesterday 前一自然日零点、7d 今日减 6 天零点、30d 今日减 29 天零点；结束上界分别为下一日零点或 today 零点，同时过滤 `completed_ms > now`。不要用固定 24 小时毫秒数推导当地日边界；DST 重复小时合并到同一个 0—23 显示桶。
5. 单步有效速度沿用 `output >= 10`、同一步存在有效开始时间、`0 < duration`、`output/duration <= 500`；未完成 chunk 样本也按其 usage 时间计算估算速度，UI 标明包括尚未完成步骤。否则仅 `valid_output/valid_seconds` 为零，不剔除 token。聚合速度是加权和式，不平均各行 tps；零有效窗口输出 null。步骤元数据中保留 `final: bool` 标识，以便对进行中估算数量作提示；开始时间为 0、缺失或非有限数均不能参与速度。
6. `cache = cache_read + cache_write`，`input` 是三者合计的 billed input；`uncached_input = input-cache`；`tokens = input+output+reasoning` 沿用本仓库 DSH 现有统计约定。overview 的 `hit_rate = cache_read/input*100`，input=0 时 0，cache_write 不能作为命中量。负数/非有限 token 归零；reasoning 与 output 暂沿用现有独立字段口径，不能额外宣称它与供应商账单完全一致。

### 3.2 快照与返回结构

- `scan()` 仍由后台执行，构建并返回一个新快照，新增内部 `_steps`（上述紧凑元数据列表）；保留 total/today/providers/models 兼容字段。缓存发布后不原地修改 `_steps` 或聚合桶。保留 `get_dsh_usage()` 的内部缓存读取职责；报表不再读取缓存里可能跨日陈旧的 today，而是从 `_steps` 查询。一次 HTTP 处理获取一次快照并捕获一次 now，windows 四窗口也共用它们。
- `query_dsh_usage(snapshot, range_, now)` 返回新字典：`{range, totals, providers, models, trend, hourly, sessions_count, data_since, undated, future, unkeyed_steps, provisional_steps}`。`totals` 包含 `steps/input/cache/cache_read/cache_write/output/reasoning/tokens/seconds/tps`；providers/models 为同样字段加 provider/model；`trend` 为升序 `{date, steps, input, cache_read, cache_write, output, reasoning, tokens, tps}` 数组；`data_since` 是全部有效日期最早值，与所选范围无关，空源为 null。undated/future 采用 totals 同构桶，但 seconds=0、tps=null，二者是整个快照的诊断，不随日期范围变化，UI 明示这一点。unkeyed_steps/provisional_steps 为当前范围数量。
- `hourly` 在 range=today/yesterday 时是 24 个 `{hour, ...totals同构桶}`，其余范围为 []；server 小时出口调用该纯查询的 today/yesterday 范围，然后做字段映射，不维护另一套步骤扫描/过滤算法。公共 daily 的 extra_rows 从 trend 中 `steps>0` 的日期产生，不能把为了专用图表补齐的空日当成有观测数据；步骤为零输出的真实日期仍保留。provider 行按 output 降序/provider 升序，model 行按 provider 升序/output 降序/model 升序，与现有排序习惯一致且稳定。
- `get_dsh_summary(range_)` 调用统一缓存刷新入口后返回 `{found, scanning, stale, refresh_error, updated_at, retry_after_seconds, ...query结果}`。错误只返回固定错误码，不含路径/日志正文。`found` 表示扫描确认存在可解析 usage，不因所选范围为空而变 false。`scanning` 是当前是否有后台扫描；stale 是快照超过 TTL；无成功快照时 updated_at=null。
- `/api/dsh/usage?range=...` 返回该摘要；无 range 时返回复制后的兼容 public 字段及刷新状态。两个分支都显式构造 public payload，严禁直接 JSON 序列化含 `_steps` 的内部缓存。非法 range 回退 today。每个 server 报表 wrapper 只在 channel 为空或 dsh 时读 DSH，避免其他单渠道查询触发扫描。

### 3.3 公共报表适配（逐端点定义）

| 出口 / 计划新增 helper | 确定的行为 |
|---|---|
| `_report_windows_response(channel)` | 一份快照聚合真实 today/yesterday/7d/30d，不复制今日值；data_since 合并取最早；保留其他来源所有字段 |
| `_report_channels_response(range_)` | 所选范围 token 或 steps 非零时追加 DSH 明细行；summary 在 found=true 时始终保留 DSH，即使范围无使用；范围会话数独立字段，不伪装账号数 |
| `_dashboard_all_payload(range_)` | totals 使用选定范围，today 无论 range 取值都使用今日；替换旧仅 range=today 才合并分支 |
| `_report_daily_response(range_, channel, metric)` | DSH 先输出 `{b: YYYY-MM-DD, ch: dsh, v: tokens}` 日行，传给下述 db 扩展；费用/请求数未知则不提供 DSH 序列，追加 unavailable_channels；不把未知值画成 0 |
| `_report_hourly_response(date_, channel)` | 同时更新旧 labels/series 和新 date/channel/buckets，series.dsh 长度 24；buckets 的 input/output/cache_read/cache_write/reasoning/total_tokens 全部累加，requests 不追加虚构值；有 DSH 步骤时增加顶层 request_count_exact=false、request_unavailable_channels=['dsh'] 提示缺 DSH 请求数，不能用无指标限定的 unavailable_channels 把 DSH token 系列误判为不可用 |
| `_dsh_channel_overview(range_)` | 映射 range totals 到 total_tokens/total_input_tokens/uncached_input_tokens/total_output_tokens/total_reasoning_tokens/cache_hit_tokens/cache_write_tokens/hit_rate；另返回 steps/session_count/avg_tps；request_count=0、request_count_exact=false、total_cost_usd=null、today_only=false。DSH 单渠道概览费用空范围也为 null（来源无费用能力）；与公共空窗费用=0 的约定分别测试 |
| `_dsh_channel_trend(date_)` | 从同一小时聚合返回 24 行，保留 input/output 别名以及 hour/total_input_tokens/total_output_tokens/total_reasoning_tokens/total_tokens/cache_read_tokens/cache_write_tokens；与 hourly.buckets 逐小时勾稽 |

`db.report_daily` 计划增加 keyword-only 参数 `extra_rows=(), extra_unavailable=()`，输入仅为 server 已聚合的通用日行及不可用渠道名，不调用 dsh_api、不访问日志。在 SQL 得到原始日行后合并 extra_rows，再提取共享 `_format_report_daily(rows, range_, metric, unavailable)` 完成排序、粒度和零补齐：all 根据本次已筛选来源的合并最早/最晚日决定（>180 天月，>60 天周，否则日）；周标签使用与 SQLite `%Y-W%W` 一致的 Monday-first week 00 规则，不能替换成 ISO 周；月份 YYYY-MM。修正现有 span 使用 MAX(lo) 且未按 channel 筛选的问题是本次跨来源粒度对齐的必要部分。非 all 维持日粒度；空源输出 labels=[]、series={}。已有参数调用继续有效，非 DSH 调用不传 extra 参数。

实现时必须替换 db.py:2482 的 `if not segs: return ...`：无数据库段时跳过 SQL 得到 rows=[]，仍合并 extra_rows 并进入 formatter（纯 DSH 查询必经）。SQL 有段时始终先查询日粒度别名 b/ch/v，不先在 SQL 外层折周/月。formatter 对相同 bucket/channel 求和，输出 labels 升序、series 按既有渠道顺序（未知来源稳定追加）；extra_unavailable 与既有不可用来源去重合并。原始输入列表不修改。

公共报表计数/费用：DSH `requests=0` 只作为合并占位，不解释为真实零请求；渠道行 UI 根据 `channel=dsh` 显示 `—`，专用区和 overview 显示 steps。纯 DSH 有数据的窗口费用为 null；混合窗口保留已知费用小计并 `cost_partial=true`，request_count_exact=false。server 合并后显式设置这些标志，不能只依赖 `db._win_merge`（它按 requests>0 判断来源）。公共无任何使用的空窗费用仍按已有空态约定为 0；DSH 概览特例见接口表。totals/window 有 DSH 步骤时附加 `request_unavailable_channels=['dsh']`、`cost_unavailable_channels` 合并既有列表；没有入选 DSH 步骤时不污染其他来源的精确度/费用标志。daily 的不可用来源按 found 且 channel 范围匹配标注，纯 DSH requests/cost 序列为空；tokens 仍完整可见。

比较指标本次选择保留数据库来源的同口径比较：先计算原 db 窗口 compare，再合入 DSH 的窗口 token，compare 不据合并后的 today 重算；当 DSH 存在时明确返回 `excluded_channels=['dsh']`，UI 标注“涨跌与异常判断不含 DSH”，纯 DSH compare 为 `{pct:null, insufficient_sample:true, spike:false}`。保留 `includes_dsh_today` 兼容字段，含义仅为今日显示值是否加入 DSH；同步更新旧文案和测试，不把“历史已接入”等同于“请求样本阈值已可比较”。每日/范围用量与秒速能力仍完整交付。

### 3.4 后台刷新、范围变化与失败恢复

保留 15s TTL 和失败后 60s 退避，删除 `_fail_count >= 3` 后永久不自动刷新的拦截；degraded 可保留诊断用途，但 HTTP 不再走同步全扫描。用一个锁保护扫描启动/完成/发布状态，锁内不解压：并发 HTTP 只启动一个 worker；scan_sync 作为测试/内部工具与 worker 共用防重入机制（Condition 等待正在运行的一轮，完成或失败后返回/抛错），不得并行扫描或覆盖更新快照。

初次请求：无快照且 scanning=true 显示“扫描中”；成功扫描无可用 usage 才显示未发现数据；失败则显示固定错误提示与重试按钮。有快照刷新失败时保留相同 range 的旧内容并显示“更新失败/上次更新时间”，不隐去整个区块，也不将旧范围数字放在新范围标题下。

前端增加一个 DSH 刷新调度器（由 showPage/visibilitychange 管理），统计页或首页 all/dsh 可见时才活动：默认每 15s 重取；scanning=true 时 1s 后查状态（单轮快速查询累计最多 30s，超出后回到 15s）；失败按 retry_after_seconds（最多 60s）退避，不清除快照；隐藏页面取消 timer、使请求序号失效，恢复可见立即重取。只有一个自动刷新周期，常规手动范围请求可以替代旧范围在途请求但必须有序号隔离，自动周期不能叠加请求或 toast。首页从 windows（all）或 channel-overview（dsh）的 `dsh_status` 顶层对象获得状态，以同一节奏刷新当前报表；其结构为 get_dsh_summary 的六个状态字段 found/scanning/stale/refresh_error/updated_at/retry_after_seconds；channel-trend 仍返回数组，不能为塞状态改变形状。常规手动/自动同步完成也调用同一个调度入口，不能启动第二套 DSH timer。`scanning` 表示 worker 状态，不等于有无数据；`retry_after_seconds` 为退避剩余时间（无退避为 0），HTTP 错误缺状态时前端固定退避 60s。重试按钮只重新读取同一入口并遵守退避，退避未到时禁用并显示剩余等待；不新增绕过锁/退避的强制扫描接口。

`loadDshUsage` 的缓存包含 range，响应只有在序号和 range 与当前相符时才能发布；切换范围若没有该范围缓存先显示加载状态。`applyLang/rerenderCharts/updateStatsScopeHint` 只用匹配当前范围缓存；旧状态 dshDim 和 dsh-dim 事件处理同时删除，避免删除 DOM 后 null.addEventListener 中断整个 bindEvents。
