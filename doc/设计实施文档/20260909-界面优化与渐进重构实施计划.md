# GoGauge 界面优化实施计划（深色主题优先）

> 日期：2026-09-09
> 状态：计划文档，尚未实施应用改动；逐轮审查结论见第九节。
> 用户偏好：主要使用深色主题，兼顾易用性与适度重构。
> 调研代码基线：`8e9fd63`；行号用于定位，实施时以符号与当前源码为准。
> 本轮交付：深色视觉精修、完整主题切换与重启恢复；后续功能见第七节。

## 一、目标、范围与取舍

保留中性黑灰底、紫色主色和现有七个渠道的身份色，改善深色下的文字、按钮、卡片、表格、图表和状态反馈。沿用 Python + pywebview + 原生 JavaScript + Chart.js，重构限于主题变量、颜色读取、主题偏好保存及启动链路。

| 方案 | 结果与代价 | 结论 |
|---|---|---|
| 只换背景颜色 | 成本低，但按钮对比度、图表固定色、主题重启恢复仍有缺口 | 不足以完成本次优化 |
| 组件与图表统一深色规范，补齐主题启动链路 | 改善日常主使用场景，改动集中且可分项验收 | 推荐 |
| 全页面重写并引入框架 | 带来构建与数据功能回归成本 | 本轮不采用 |

本轮覆盖：全部/单渠道首页、统计页及各本地区块、使用记录、可选账户总览、设置、关于、应用自身的欢迎页、用户菜单、确认弹框与 toast。浅色维持现有视觉与功能兼容，不同步重设计。

第三方登录网页、WebView2 系统对话框和操作系统托盘菜单不受本应用 CSS 控制：只回归其正常使用，不承诺改造成深色。应用自有欢迎页与弹框在范围内。

本轮不改变统计口径、接口的业务查询语义、采集、账号管理、列数量或每页 7 条。允许一个必要的持久化扩展：现有 settings JSON 增加可选 `theme`，复用已有设置接口，服务端首页携带主题初值，桌面主窗口采用对应背景；无数据库表结构迁移，不修改用量或凭据数据。这是保证换端口重启恢复所需的最小主题链路。

## 三、深色设计与验收规范

### 3.1 基础与组件

- 背景从现有 `--bg #111112`、`--card #1a1a1c`、`--muted #202022` 起步；保留主色和渠道色。减弱过重阴影，利用间距、细边界表达卡片与内部小块的关系。
- 核心 KPI 以近白数字为主，渠道点/短条保留颜色识别；标题、数值、单位与解释形成层级。正文建议 13–14px、表格 12–13px、核心数值 22–26px，在现有布局内验证。
- 所有可用控件标签、正文、表头、轴文字、图例、tooltip 和错误说明，对其实际背景目标不低于 **4.5:1**。禁用与纯装饰元素不套用文字目标，但禁用状态必须可辨，错误和未知值说明不能以禁用样式规避验收。
- 关键 focus/selected 标记与相邻背景目标不低于 **3:1**；装饰分隔线无需使用相同强度。颜色不是唯一提示，保留文字、位置和图形标记。
- 卡片统一 8/12/16/24px 间距节奏。表头轻微提层、分隔线低亮度、行 hover 连贯；已有 active/selected 控件保留状态，不为普通记录行新增选择业务。
- 实现 `.select:focus-visible` 和 `.sw input:focus-visible + .slider`，以及按钮/导航/pill 的焦点。真实 input 不能因画在零尺寸元素上的 outline 而“测试有规则、用户看不到”。
- 对应用自有菜单、弹框、toast、空态、错误和骨架统一背景/边界；`color-scheme` 随主题变化，原生 select 和滚动条在 WebView2 中人工复核。
- `prefers-reduced-motion` 降低骨架扫光、页面入场与控件过渡；保持 toast 现有定时关闭行为，不因取消动画使节点不消失。
- 本轮只改善现有键盘控件的视觉反馈；新增弹框焦点捕获、列选择、整页导航重排属于后续交互任务，不列为本轮交付门槛。

### 3.2 变量与消费点

在 `style.css` 的 root/dark 块定义变量；浅色默认值复用原值，深色覆盖不得靠全局换色误伤浅色。D1 确定最终 hex 后记入测试和设计记录；以下名称及消费范围作为契约。

| 变量组 | 变量/接口 | 主要消费点 |
|---|---|---|
| 主按钮 | --button-primary-bg、--button-primary-hover、--button-primary-text | .btn-primary 及 hover；不直接重定品牌 --primary |
| 刷新 | --refresh-hover-text | .pill.small.refresh:hover，背景可保留现有 amber |
| 危险 | --danger-text、--danger-hover-bg、--danger-hover-text | .btn-danger、.badge.no、#codex-error、两张记录表内联错误文字；普通图形红色另保留 |
| 浮层/焦点 | --surface-popover、--border-popover、--focus-ring | user-menu、modal-card、toast、focus-visible；表格选中只用于已有状态 |
| 指标 | --chart-input/output/reasoning/cache/cost/extra | 替代 COLOR 与 chartModel 第六硬编码色；实际展开为六个独立变量名 |
| 账号 | --account-1 至 --account-6 | 替代 OV_COLORS；账户卡和 sparklineSvg 使用 CSS var，沿用现有顺序和取模分配 |
| 提示框 | --chart-tooltip-bg/text/border | 全部 Chart.js tooltip，保留各图已有 callbacks |

图表初始深色指标色建议从现有渠道浅亮色与指标色出发，按真实深色背景验证；不修改系列语义、模型排名、统计公式、轴范围、线条顺序或当前渠道身份色。

### 3.3 图表主题公共逻辑

保留普通脚本加载，暂不拆 ES module。新增小函数 `chartColors()` 在每次绘制时读取六个指标变量；`chartThemeOptions()` 返回当前主题 legend/ticks/grid/tooltip 所需的具体颜色值。Canvas 不能直接使用 `var(--...)`，必须经 `getComputedStyle(...).getPropertyValue(...).trim()` 解析，且提供已知合法颜色回退。

十个图表逐项覆盖：`chartToday`、`chartModel`、`chartTrend`、`chartZcodeTrend`、`chartClaudecodeTrend`、`chartCodexTrend`、`chartOvTrend`、`chartReportStack`、`chartReportDonut`、`chartReportHourly`。DSH 没有独立趋势图，不新增虚构图表。

DOM/SVG 的账号、渠道颜色继续用 CSS var，主题变化即时生效，不能在缓存账号对象上保存一次性颜色快照。Chart.js 配色在构建时读取；合并 options 时保留各图 tooltip callbacks、轴单位、多轴、legend 显隐和事件回调。

保持 `applyDarkMode → rerenderCharts → refreshIcons` 唯一入口、noAnim、图表销毁和可见尺寸保护。每次改变主题只更新当前页面图表与已有图标；进入隐藏页后按当前主题绘制。禁止直接编辑 `chart.umd.min.js`。

### 3.4 主题持久化与首次绘制

**存储契约**：在 `db._DEFAULT_SETTINGS` 增加 `theme: None`；`get_settings/save_settings` 只接受 `light/dark`，非法值或 null PUT 忽略并保留当前值，与既有忽略无效设置的风格一致。读取历史损坏值按 None 对待。保存沿用现有锁、原 payload 合并与事务，不能覆盖 key_names、active_account_id 或其他设置。默认 None 表示未设置，实际显示仍为浅色。

**首页预置**：修改 `server._static_response` 的 index.html 专用路径，使用受限枚举输出 `data-theme-preference="light|dark|unset"`，无需等待任何 API 请求。响应重算 UTF-8 Content-Length，仍 no-cache；不注入完整 settings、账号或凭据。其他静态资源响应保持原样。无偏好与读取失败使用 unset。

**首屏顺序**：`index.html` head 内的同步小脚本放在主样式链接之前，只设置根元素主题和 color-scheme，不调用依赖 DOM/Chart 的 applyDarkMode。选择顺序是已保存服务端 theme → 当前来源可读且为 1/0 的旧 gousage-dark → 默认 light。非法旧值或读取异常走默认。app.js 初始化从已应用根主题建立 state；版本请求延迟或失败不能重置主题。

**旧偏好迁移**：仅服务端为 unset 且当前来源旧键有效时，初始化后保存一次该选择。随机旧端口或旧临时 WebView 存储中已不可访问的数据不能承诺自动找回；这种情况下用户重新选择一次后，新持久化链路保证后续重启恢复。不更改端口策略或强制打开持久浏览器配置。

**用户切换**：保留 `applyDarkMode(on)` 为纯界面应用与旧键兼容写入，持久化由独立的 `setThemePreference(on)` 处理。顶栏与设置主题按钮都调用该入口；启动应用主题、语言/货币切换与图表重渲不重复保存。沿用 `PUT /api/settings`，请求体只有 theme。

保存操作采用单个串行队列与最新意图合并，保证快速 dark→light→dark 最终持久化为 dark；后到响应不能回写旧主题。失败时当前界面保留用户选择，显示一次“主题未保存，重试”，重试仍走同一队列，不宣称重启一定记住失败写入。中英文文案都加入 I18N。主题切换允许必要的 settings PUT，**不得额外请求用量、额度、报表或触发同步**，替代不准确的“切主题零网络请求”表述。

**原生底色**：`main.main` 在创建主窗口前读取已保存主题，使用与 root/dark --bg 对齐的 `background_color`，避免 HTML 绘制前的原生白底。只处理主窗口；不重绘第三方登录页。未设置或偏好读取失败时采用原有浅色默认。测试约束主窗口底色与 CSS 基线一致。网页刷新由首页预置恢复；真正退出（而非收进托盘）重启后也须验证。

## 六、风险与回退

5. 启动 seed 只允许枚举，无 settings 整体注入；持久化失败保留当前视觉并提示未保存，不能误报重启成功恢复。
