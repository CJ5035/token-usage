## 模拟手段说明（先读）

- **手段A 断网**：关闭 Wi-Fi / 拔网线。注意局限：首页与统计页主体数据来自本地 DB，**断网不会使其失败**，断网只影响汇率（open.er-api.com）与 ZCode 配额（GLM 端点）等外呼数据。要模拟"请求失败/挂起"必须用手段B/C。
- **手段B 后端注入 sleep（模拟后端挂起，触发前端 20s 超时）**：临时在 app/server.py 对应 route 分支首行加 `time.sleep(25)`（文件顶部已 `import time`），**验收后移除**。注入点：

| 端点 | server.py 行号 |
|---|---|
| GET /api/dashboard | :1213 |
| GET /api/zcode/quota | :1267 |
| GET /api/report/channel-overview | :1470 |
| GET /api/report/daily | :1448 |
| GET /api/update/check | :1165 |

- **手段C 5xx**：临时把对应分支响应改为 `_json_response(handler, {"ok": False}, 500)`，验收后还原。
- 行为口径：后端 ZCode 配额失败合同为 **200 + 错误 dict**（fetch_quota 永不抛异常），前端 `loadZcodeQuota` 的 catch（toast）只在**请求级失败**（5xx / 超时 / 连接拒绝）触发——⑤ 有路径区分项。

## ④ 场景4：前端超时 + 统计页失败占位 + 重试（核心新交互）

**操作**：手段B 注入 /api/dashboard（server.py:1213 分支首行 `time.sleep(25)`）→ 重启应用 → 切到统计页（主动加载）→ 等待约 20s。

- [ ] **~20s（远早于注入的 25s）出现失败反馈**：KPI 行位置一条**通栏红色错误条**「加载失败： 请求超时，请检查网络后重试」+「重试」按钮（本地化文案而非浏览器英文原文 = 20s 超时与 TimeoutError 本地化同时生效）
- [ ] **三处伴随状态（均为预期，防误判渲染缺陷）**：`stats-total-cards` 区为上述通栏占位；`stats-detail6` 区**空白**；趋势图区为**留白 canvas**（灰色骨架遮罩已移除）——整体无"一块错误 + 其余骨架"的半死状态
- [ ] **重试闭环**：还原注入（移除 sleep）重启后回到占位现场，点「重试」→ 骨架恢复 → 数据正常渲染（占位被真实 KPI 覆盖，无残留）
- [ ] **反馈幂等**：再次注入失败并主动加载 → 占位再次出现（不跳变 toast、不残留半新半旧数据）
- [ ] **quiet 基线**：数据正常显示后触发静默刷新（等 5s 配额自动重试或重命名账号触发）且后端失败 → **已有数据不被打碎**，无占位无 toast（维持现状静默）
- [ ] **隐藏容器残留观察**：统计页失败后切到首页单渠道页签 → 成功渲染时占位被真实数据无条件覆盖（usage-blocks/overview-grid 同名容器），无占位残留
