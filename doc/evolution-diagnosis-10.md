## 1. 问题陈述

统计页三个本地用量卡（ZCode / Claude Code / DSH）内的六张明细表均无表格内横向滚动容器：窄窗口（出厂 DPI 缩放下即默认窗口）下，表格固有列宽与超长单元格内容都会把表格撑到超出卡片，溢出由 `#page-stats` 整页横向滚动消化——滚动条 thumb 颜色与背景几乎同色不可发现，滚动时 KPI 卡、图表等全部内容一起移出视野。其中 DSH 表还额外缺失 td 级单元格防线（ZCode/CC 表有），超长渠道/模型名会把表格撑得更宽。

## 2. 静态证据确认（file:line 均为当前代码）

1. **三卡表格均无滚动容器**：
   - ZCode 卡 `card zcode-stats`：`index.html:126-127` 两表裸 `<table class="tbl">`；
   - DSH 卡 `card dsh-stats`：`index.html:141-142` 两表裸表；
   - Claude Code 卡 `card zcode-stats`：`index.html:151-152` 两表裸表。

2. **td 级防线只覆盖 zcode-stats 卡**：`style.css:470-471` `.zcode-stats .tbl td { max-width: 260px; overflow: hidden; text-overflow: ellipsis; }`（含自述注释"渠道/模型名为用户自定义字符串, 超长单元格省略防破版"）。DSH 卡类名 `dsh-stats`（`index.html:131`）不在覆盖范围；style.css 全文无任何 `.dsh-stats` 溢出规则。
3. **全表 nowrap 基础规则**：`style.css:295` `.tbl td { ... white-space: nowrap; ... }`——单元格不折行，列宽由内容决定。
4. **整页横滚 + 隐形滚动条**：`style.css:69` html/body overflow:hidden、:103 .app、:116 .main、:117 .page 全链 hidden；`#page-stats`（:122）仅显式 `overflow-y: auto`（同一行还有 `overflow-y: overlay` 废弃值覆盖声明——新 WebView2 按 auto 处理，overflow-x 计算值随之变 auto 的结论不变，但该废弃值已列入候选清单备选池 #2，阶段3 若动 overflow 链需一并核对）；自定义滚动条 `::-webkit-scrollbar { width: 8px; height: 8px }` thumb `background: var(--border)`（浅灰，与卡片/页面背景对比度极低）。
5. **数据源为用户自定义字符串**：DSH 渠道表 `p.provider`（`app.js:1033`）、模型表第一列 `m.provider` + 第二列 `m.model`（`app.js:1041-1042`，v1 漏列第一列已补）；ZCode/CC 表同族（`p.provider`/`m.model`，有 td 防线兜底但列宽溢出无兜底）。应用对命名无长度约束。
6. **契约测试固化了现状**：`tests/test_narrow_layout.py:88-92` 反向强断言 `assert html.count("tbl-scroll") == 1`（注释自述"tbl-scroll 包裹仅用于渠道明细表"）——EVOLUTION-8 轮"滚动形态仅限 report 表"的历史决策证据，本轮修复必须同步改写该断言，否则 CI 阻塞。

### 3.2 长名加剧（DSH 表无 td 防线）

- 注入实验（对象：DSH **渠道表**首列，102 字符渠道名）后表格被撑到固定 **1177px**（与视口无关，nowrap min-content），813/911/1024/1220 四个宽度下最后一列 right=1244 全部不可见，整页横滚量最大 457px。
- 临界实验：60 字符在 813~1220 全宽度下数字列可见（不触发）；102 字符全宽度触发。**触发阈值在 60~102 字符之间**（随字符宽窄浮动），v1 报告"60+ 字符即可触发"的表述已修正。
- 1280px 宽度下 55 字符被列宽再分配吸收（v1 实验，维持）。

### 3.3 自救路径实测（修正 v1 定性）

- `#page-stats.scrollLeft` 可设置：0→456（maxScroll 457），**横向滚动可达**——v1"裁死不可达"定性错误，予以修正。
- 但可发现性极低：滚动条 thumb 为 `var(--border)`（亮色下与页面背景近似同色）、高仅 8px；普通鼠标滚轮不触发横滚（需 shift+滚轮/触摸板/拖动底部滚动条）；溢出发生时无任何"内容被截断"的提示。
- 横滚代价：`#page-stats` 是整页滚动容器，滚动时 KPI 卡、Token 构成、图表等**所有内容一起移出视野**，上下文丢失；而 report 表先例（EVOLUTION-8）是表格内局部滚动，其他内容不动。

## 4. 根因

**直接根因**：统计页三卡六表均不具备表格内横向滚动容器（.tbl-scroll），窄窗下列宽总和超视口的溢出只能落到 `#page-stats` 整页横滚——滚动条近乎隐形、无截断提示、滚动代价是全页内容位移。DSH 表在此之上还缺 td 级长名防线（ZCode/CC 有），长自定义名把表格撑得更宽、溢出更多。

**系统性根因**：表格组件落地时防线依赖开发者记忆同步，无契约测试拦截；EVOLUTION-8 修复 report 表后，`test_narrow_layout.py` 的 `count("tbl-scroll") == 1` 反而把"仅 report 表有滚动"固化成了不变量，客观上阻止了防线向同类组件扩散。

- **窗口条件（按代码推算 + 实测校准）**：初始窗宽 = `min(WINDOW_SIZE=(1280,840), 工作区逻辑宽-60)`（`app/main.py:25,488-489`，`_screen_workarea_logical` 返回逻辑像素）。1080p@125% → 1280；1080p@150% → 1220；1366×768@125% → 1033；1366×768@150% → 851。用户手动缩窗下限 = min_size=(1000,680) 物理像素（125% DPI → 800 CSS；150% DPI → 667 CSS）。
  - **当前真实数据即触发数字列不可见的表（实测）**：ZCode 渠道表（8 列，851px 起末列不可见）、ZCode 模型表（9 列，1033px 起末列不可见）、DSH 模型表（6 列含图标模型名，851px 起末列不可见 right=931）——1366×768 全屏笔记本（125%/150% DPI）**出厂默认即触发**；1080p@150%（1220px）不触发。
  - **当前数据不触发的表（实测）**：CC 两表（6 列，800/911/1033px 末列均可见 right=773/885/1007，v2 曾并列实锤、第 2 轮实测否定）；DSH 渠道表（5 列，800/851/1033px 末列均可见 right=773/825/1007）。
  - **DSH 长名加剧**：≤1220px 全部触发（102 字符）。
- **数据条件**：ZCode 两表与 DSH 模型表溢出为固有列宽，**当前真实数据即触发，无需任何用户自定义长名**（实测实锤）；DSH 两表的长名加剧需要用户自定义 60~102+ 字符渠道/模型名（模型表第一/二列 `m.provider`/`m.model` 与渠道表首列同为无 td 防线自定义字段，推测性触发面，不影响定级——固有列宽溢出已独立实锤）。
- **自救评估（v2 修正口径）**：横向滚动**可达**（scrollLeft 实测）+ 拉大窗口可达（min_size 不限制向大拉宽，v1 归因错误已修正）；但滚动条几乎不可见、无溢出提示、普通滚轮不触发，可发现性极低；且横滚是全页位移，上下文丢失。真正"难以自救"的组合是低物理分辨率屏（1366×768@150% 全屏 851px < 表格需求宽）+ 不了解横滚操作的用户。

## 6. 严重等级与损伤指数

- **P2（体验折损，非功能受阻）**：数据不丢失，存在自救路径（拉大窗口/横滚），但默认窄窗下数字列不可见 + 恢复操作不可发现。
- **损伤指数 6/10（维持）**：论据替换——v1 的"裁死不可达"（已修正）替换为：① 三张表**当前真实数据即触发数字列不可见**（实测：ZCode 模型表 1033px 起、ZCode 渠道表与 DSH 模型表 851px 起——1366×768@125% 全屏仅模型表触发、@150% 三表全触发，出厂默认场景覆盖实测）；② 溢出消化方式是整页横滚，与 EVOLUTION-8 已修复的 report 表（表格内滚动）行为不一致，用户在统计页遭遇的是更差形态；③ 滚动条不可发现 + 无截断提示，状态可见性（尼尔森 #1）与防错（#5）双缺口；④ 未到 P1 因：自救路径存在、数据无损、只影响统计页本地用量区。
- 与 EVOLUTION-8 同族同分（其"数据自列裁死"P2 6/10）：本次的固有列宽溢出触发门槛更低（无需长名），但自救可达性更高（横滚可达 vs 当年 report 表无滚动容器），综合相当。

## 7. 用户体验影响

- 触发用户（1366×768 全屏笔记本为主）在统计页：**ZCode 两表与 DSH 模型表**右侧数字列不可见（实测：ZCode 渠道表末列"平均首字延迟"、ZCode 模型表末列"平均输出速度"、DSH 模型表末列"平均 tok/s"；@125% DPI 仅 ZCode 模型表触发、@150% DPI 三表全触发，见 §6①），页面底部有一条几乎与背景同色的横向滚动条；发现并拖动后，整个页面（含 KPI、图表）左右位移，读一个数字需要反复横滚对照表头。
- CC 两表（实测不触发数字列丢失）：窄窗下末列超出卡片边缘但仍在视口内可见，无数字列丢失——但结构上同样无表格内滚动容器，防御缺口与本问题同源。
- DSH 长名用户叠加：表格被撑到 ~1177px，横滚距离更长，且渠道名本身也被视口截断。
- 满意度损伤集中于低分辨率笔记本 + 重度本地用量用户——恰是此类工具的核心使用人群画像。

## 8. 修复收益
