# 基元律动账号 Token 用量接入

> 创建日期：2026-09-10
> 状态：需求与代码探索完成（同日两轮公开前端资源探测，接口契约已从官网前端 JS 确认）；待登录后验证真实响应；尚未实施

## 一、需求概述

在 GoGauge 新增「基元律动 / TokenRhythm」云端渠道，通过官网账号登录获取该账号的 Token 用量。支持多个账号独立保存凭据、同步、切换和统计，并在渠道报表中展示。

## 二、功能边界

### 包含范围

- 设置页新增基元律动账号入口，复用已有登录、重登、重命名、切换和删除交互。
- 按官网用户 ID 区分账号；同一账号下所有 API Key 的用量通过账号接口统一获取。
- 读取账户级总量、输入、输出、缓存读写、模型统计及分页明细，接入今日、7 天、30 天和历史范围。
- 后台同步沿用现有调度设置，失败保留已有数据，过期提示重新登录。
- 缓存字段缺失或不完整时保留该状态，不把未知显示为真实零值。

### 不包含范围

- 创建、删除、停用 API Key，充值、兑换、账户资料修改。
- 获取对话正文、提示词或完整 API Key。
- 自动填写密码、代收验证码或绕过登录。
- 没有证据的额度窗口、会话数和速度估算。

认证细节补充确认：

- 正式前端**不使用 Bearer token**（`useMock` 为 false 时 token getter 恒为 `undefined`），会话完全依赖 cookie（`credentials: 'include'`）——与 GoGauge 现有 BAI/CommandCode 的 WebView 登录捕获 cookie 模式天然兼容。
- GET/HEAD/OPTIONS 请求**无需 CSRF**；仅写操作从 cookie `tr_csrf` 读值附 `X-CSRF-Token`。GoGauge 只读接口全部为 GET，不涉及 CSRF。
- 登录成功判定可直接复用 CommandCode 的稳健规则（域匹配 + 非空会话 cookie 全量 jar 收集），再以 `GET /api/me` 验证身份取 `user.id` 作去重键。
- 官网前端内部标识为 `jiyuan_lvdong_*`（localStorage 前缀），证实运营主体即基元律动。

按 API Key 维度（`/api/api-keys/usage`）与账户维度（`/api/usage-summary`、`/api/usage/panel`）均可获取用量；本需求「按账号获取」采用账户维度主口径，Key 维度作为 `key_id` 补充信息可选。

### 登录后必须核实

1. 会话 Cookie 的名称、域、过期行为（前端只知 `tr_csrf` 与"会话 cookie 非空"，真实会话 cookie 名需登录后实测）；`auth/me` 的真实成功和过期响应。
2. `items` 明细项的字段全集（缓存 token 是否逐条返回）、分页上限及排序方向。
3. 总 Token 与输入、输出、缓存的包含关系，失败请求是否进入面板统计。
4. 缓存 Token 是否逐条返回，还是仅在汇总层完整；若仅汇总可用，独立保存范围快照，不能伪造逐条缓存数据。
5. `all` 可查询的历史深度及日期边界，累计数与逐页明细是否一致。

## 四、核心实体定义与接入方案

### TokenRhythmAccount

- `source: str = "tokenrhythm"`：新渠道标识。
- `id: int`：沿用本地 accounts 主键。
- `workspace_id: str`：保存官网稳定用户 ID，用于 `(source, user_id)` 去重。
- `token: str`：沿用现有凭据列保存官网域内 Cookie jar JSON，仅在本机使用。
- `name: str`：沿用账号显示名；重登不能覆盖用户自定义名。

登录必须严格匹配官网 hostname，并用 `auth/me` 验证真实用户身份。重登目标与登录返回用户不一致时，不得把其他账号的历史记录归属到目标账号。

### TokenRhythmUsage（拟新增独立存储）

- `account_id: int`、`record_id: str`：组合唯一键，避免官网记录 ID 在不同账号或渠道重复。
- `created_at: str`：标准化时间，聚合明确使用日期边界。
- `model: str`、`total_tokens: int | None`、`input_tokens: int | None`、`output_tokens: int | None`。
- `cache_read_tokens: int | None`、`cache_write_tokens: int | None`：保留未知状态。
- `cache_read_complete: bool`、`cache_write_complete: bool`：准确表达数据完整性。
- `cost_cny: str | None`：保留官网原币值，不能直接写入 USD 列。
- `synced_at: str`：最近同步时间。

实际 schema 在登录取样后确定；总量优先采用官网定义，不能在未知输入包含关系时再次叠加缓存。

### 方案选择

建议复用现有账号管理与同步调度，增加独立的 TokenRhythm API 客户端和用量表。现有 `usage_records` 没有独立总 Token 列，缓存字段默认零且费用固定为 USD，直接映射容易丢失总量、缺失状态及币种信息。

另一种做法是扩展所有云端渠道的公共用量表，但会影响现有渠道迁移和统计，当前需求不优先采用。

#### 费用口径三选一（GoGauge 现状：内部统一 USD 存储，人民币仅为显示层换算）

GoGauge 现有费用体系：`cost_usd`/`cost_raw`（1e-8 USD）为唯一存储口径，跨渠道 `SUM(cost_usd)` 求和，前端按用户偏好 CNY/USD 切换显示（open.er-api.com 汇率 24h 缓存）。OpenCode/CommandCode 服务端返回 USD；BAI/ZCode/Claude Code 本地定价表估算 USD（`_LOCAL_EST_CHANNELS` + est-badge 徽标）；Codex 费用恒 NULL 显示 `—`（`fmtOptionalMoney`）。基元律动是首个费用**原生 CNY** 的渠道，三种处理：

- **方案 A（原草案首版）**：保留 CNY 原值，跨渠道 USD 汇总位置显示 `—`。受影响位置（仅费用数字，token 类全部正常）：首页 KPI 总费用/今日总费用、多账号 7 日费用趋势折线（基元律动费用被排除在 `costSum` 之外）、用量统计页模型排行费用维度/全渠道费用趋势线/数据源占比堆叠图 cost metric/汇总行费用、使用记录明细费用列。单渠道视图费用卡可正常显示 CNY 原值。
- **方案 B（推荐）**：同步时按实时汇率换算 `cost_usd = costCny / (USD→CNY rate)` 入库，渠道加入 `_LOCAL_EST_CHANNELS`（显示 est-badge 换算标记，与 BAI/ZCode 先例一致），独立表同时保留 `cost_cny` 原值。全部页面可用，跨渠道求和口径统一；汇率缓存机制完全复用现有实现，仅换算方向为除法。
- 方案 C（公共表改多币种）：影响所有现有渠道迁移与聚合，不采用。

推荐 **方案 B**：改动集中在换算入库一处，前端零新增机制，且"换算"性质经 est-badge 明示，不与 OpenCode/CommandCode 的服务端权威 USD 费用混淆。
